# Changelog (Unreleased)

Record image-affecting changes to `manager/`, `worker/`, `copaw/`, `hermes/`, `openclaw-base/`, and `agentteams-controller/` here before the next release.

---

**What's New**

- **Worker and Team display names**: Add an optional `displayName` to Worker and Team specs, synced to the Matrix profile displayname (Worker) and Team room name (Team) behind a generation-guarded idempotency marker (`status.displayNameSyncedGeneration`), and surfaced in the Controller REST API plus `agt` create/update/get (new `--display-name` flag and `DISPLAY-NAME` column).
- **Optional Human display name**: `spec.displayName` on the Human CR is now optional — empty leaves the Matrix profile displayname unset (no `SetDisplayName` call), the CRD `required` list narrows to `permissionLevel`, and `agt create human` no longer demands `--display-name`.
- **Custom Human initial password**: Add an optional `spec.initialPassword` to the Human CR so callers can pin the Matrix password assigned on first provisioning (`legacy_password` identity source only). When omitted, the controller generates a random password and persists it into **both** `spec.initialPassword` (durable, auditable) and `status.initialPassword` on creation via a one-shot spec write-back; later edits never reset a password the user has rotated. Surfaced in the Controller REST API and `agt create human` (new `--initial-password` flag).
- **QwenPaw 2.0 runtime unification**: Migrate the Manager container from copaw 1.0.2 to QwenPaw 2.0.1 on a single venv, register projectflow/taskflow/message/filesync tools through a QwenPaw plugin instead of monkey-patching CoPawAgent, replace the physical Matrix channel overlay with the QwenPaw plugin system, read Matrix credentials directly from agent.json so the manager tools work without importing copaw at runtime, align CMS observability packages and env vars with the Worker image, inject session-file privacy policy into prompt files, set approval_level=AUTO in the agent template, bridge YOLO mode to Qwenpaw approval_level=OFF, disable the built-in QA Agent, replace start-copaw-manager.sh with start-qwenpaw-manager.sh, add explicit qwenpaw Manager and Worker runtime values alongside copaw while keeping user-facing installer defaults and image pulls on CoPaw until the QwenPaw release, make task assignment state and Matrix notification atomic with room membership validation and m.mentions delivery, preserve m.mentions metadata in streamed/edit events, make the TeamHarness MCP `delegate_task` path atomic too (validate assignee room membership — strictly `join`, not `invite` — prepare → stable-txn notification → commit assigned + event_id; the initial file publish gates the notification and the assigned/eventId commit gates success, both returning a retryable failure so an idempotent retry finishes the sync instead of reporting success with stale shared storage), and migrate a legacy Worker `.copaw` working dir to `.qwenpaw` on the qwenpaw_worker startup path only (idempotent; the migration follows the target runtime — an explicitly configured copaw Worker keeps `.copaw` and never migrates before a switch).
- **Custom model capability overrides**: `AGENTTEAMS_MODEL_VISION` and `AGENTTEAMS_MODEL_REASONING` env vars let deployments override vision and reasoning capabilities for custom models not in the built-in presets table (e.g. local multimodal models like `qwen3.6-27b-fp8`).
- **Synapse homeserver support via the MatrixOps abstraction**: Introduce a provider-agnostic `MatrixOps` business layer over the raw Matrix protocol clients, selected by `AGENTTEAMS_MATRIX_PROVIDER` (`tuwunel` default, `synapse`). Room lifecycle, membership, aliases, room metadata, system messages, membership queries (`ListRoomMembers`/`ListJoinedRooms`/`IsUserInRoom`/`IsManagerJoinedDM`), and a homeserver `HealthCheck` are implemented for both homeservers; Synapse write operations automatically recover by classifying the sender-side rejection — force-joining the acting user via `POST /_synapse/admin/v1/join/{roomID}` when they are no longer in the room, or promoting them via the admin `make_room_admin` API when they lack the required power level — then retrying the CS operation. The controller's startup `waitForMatrix` now polls through `MatrixOps.HealthCheck` instead of the protocol client.
- **Synapse support documentation**: Add `docs/synapse.md` covering provider switching (`matrix.provider=synapse`), the declarative AppService registration model (Helm-managed `app_service_config_files` vs Tuwunel's runtime admin-bot registration), the namespace security model (`AGENTTEAMS_MATRIX_APPSERVICE_USER_NAMESPACE_REGEX` escape hatch for shared Synapse clusters), token rotation workflows (runtime on Tuwunel, restart-only on Synapse), and the classified force-join / `make_room_admin` recovery paths operators occasionally see in logs.
- **Cross-implementation equivalence suite**: Add `agentteams-controller/internal/matrix/ops_exhaustive_test.go` pinning behavior parity between `TuwunelMatrixOps` and `SynapseMatrixOps` for every `MatrixOps` method — GROUP A success-path equivalence on the shared CS API surface, GROUP B wire-divergence paths (admin-bot chat on Tuwunel vs Synapse REST, plus the classified force-join / `make_room_admin` sender-recovery fallbacks), and GROUP C AppService governance divergence (declarative on Synapse vs runtime on Tuwunel) with `RenderAppServiceRegistration` struct equality across the nil-vs-set push URL branch.
- **MatrixOps convergence comment/doc maintenance**: Align business-layer comments and docs with the provider-agnostic `MatrixOps` design so homeserver-generic behavior is no longer attributed to Tuwunel. Updates `docs/architecture.md` "Matrix (Tuwunel)" → "Matrix (Tuwunel / Synapse)" with the `AGENTTEAMS_MATRIX_PROVIDER` selection and `MatrixOps` convergence notes; neutralizes Tuwunel attribution in `provisioner.go` (ManagerEnabled, `ensureMatrixToken` dual-provider reuse rationale), `provisioner_human.go` (JoinRoomAs `trusted_private_chat` is a Matrix spec preset, not a Tuwunel feature), `human_reconcile_delete.go`, `human_reconcile_rooms.go`, `manager_reconcile_welcome.go`, and `humanidentity/identity_source.go`; renames the `initializer` gateway config field `TuwunelURL` → `MatrixURL` (backed by `MatrixServerURL`, so it already served Synapse in k8s mode) and corrects the gateway route comments (the `/_tuwunel/*` route never existed — only `/_matrix` is registered; the "tuwunel" service source name is kept as the historical stable identifier).

**Bug Fixes**

- **CoPaw Team assignment handoff**: `taskflow(delegate_task)` sends the Worker assignment automatically with `m.mentions` in the Team Room (atomic pending → prepared → assigned state, stable Matrix txn_id for idempotent retries, normalize Worker aliases from the Team roster, refresh Controller-managed runtime context every minute, and reroute assignment replies from non-Team rooms to the Team Room). ([#1120](https://github.com/agentscope-ai/AgentTeams/pull/1120), [#1095](https://github.com/agentscope-ai/AgentTeams/pull/1095))
- **Docker Worker ServiceAccount token rotation**: Project short-lived tokens into per-Worker Docker volumes, refresh the token file atomically without recreating running Workers, and remove the credential volume with the Worker.
- **Worker port exposure CLI**: Encode `--expose` values as numeric ports and reject invalid or out-of-range inputs before create, update, or apply requests reach the Controller.
- **QwenPaw MCP policy startup convergence**: Persist built-in plugin MCP policies before runtime desired-state reloads so a replacement QwenPaw workspace cannot retain the pre-policy interactive approval handler.
- **QwenPaw Team policy and runtime-aware acceptance**: Merge Team and Worker channel-policy overrides into QwenPaw `runtime.yaml`, wait for public plugin/API state before integration assertions, and verify prompt/config files from the runtime location that consumes them.
- **QwenPaw 2.0 tool execution**: Preserve QwenPaw's asynchronous tool-result stream while sanitizing output, and allow only the built-in TeamHarness and Workerflow MCP drivers to run without an unavailable interactive approval prompt.
- **QwenPaw package and Team storage access**: Preserve referenced members' effective Team name across independent Worker reconciles, update MinIO policies without detaching active Workers, revoke access on detach, and grant Workers read-only access to centrally uploaded AgentSpec packages.
- **QwenPaw inline prompt compatibility**: Project Worker identity, SOUL, and AGENTS content through runtime desired state and apply it to both the native QwenPaw workspace and the Worker root storage contract.
- **Integration failure diagnostics**: Export AgentTeams container state and timestamped logs with CI artifacts, classify QwenPaw startup errors without exposing their message contents, and stop the TeamHarness shard after startup failures instead of hiding the cause behind cascading timeouts.
- **QwenPaw local startup readiness**: Select and propagate the QwenPaw Worker image across install backends, then wait for the runtime-owned `runtime/runtime.yaml` object before creating a local Docker Worker.
- **QwenPaw 2.0 runtime compatibility**: Adapt the QwenPaw Worker image, custom Matrix Channel, and native plugins to QwenPaw 2.0.1 startup and schema contracts.
- **Multimodal model image support**: Add `supports_multimodal` and `supports_image` to `agents.defaults` in generated openclaw.json when the selected model supports image input, so QwenPaw does not strip images at the framework layer. Fixes #931.
- **Install script model env passthrough**: Pass custom model override env vars to the Controller container so that `AGENTTEAMS_MODEL_VISION` and related settings actually reach the config generator.
- **Bridge model capability propagation**: Propagate model `input` modalities from openclaw.json through `_write_providers_json()` so QwenPaw's `ModelInfo` receives `supports_image`/`supports_video`/`supports_multimodal` flags instead of relying on fail-open defaults.
- **Manager diagnostic loops**: Manager prompts and Worker lifecycle guidance stop repeated no-op troubleshooting commands and treat a missing Worker in `agt get workers` as the deletion boundary instead of looping on Matrix room probes. ([#975](https://github.com/agentscope-ai/AgentTeams/pull/975))
- **Matrix kick idempotency and ForceLeaveRoom fallback**: Tighten the kick-failure matcher so only the target-not-in-room idempotent case (`"target user is not in"` / `"is not in the room"` / `"not a member"`) returns nil — previously the matcher also swallowed real `"cannot kick user"` power-insufficient errors as no-ops. The `shouldForceLeaveAfterKickError` escalation matcher now recognizes both Tuwunel-style (`"not have enough power"`) and Synapse 1.127-style (`"cannot kick user"` / `"cannot unban user"` / `"not in room"`) power/sender errors, so `ForceLeaveRoom` and `RemoveMember` route to the correct provider-specific fallback (admin-bot `force-leave-room` on Tuwunel; classified sender recovery on Synapse — force-join via `POST /_synapse/admin/v1/join/{roomID}` for not-in-room, `make_room_admin` + CS kick retry for power-insufficient) instead of silently dropping the failure.
- **AppService management handler hardcoded TuwunelClient**: Replace the hardcoded `matrix.TuwunelClient` construction inside `appservice_mgmt_handler.go::RotateToken` with a provider-aware path through the injected `MatrixOps` / `matrix.Config`. On Synapse the endpoint now returns HTTP 501 with Helm-guidance JSON (declarative registrations cannot be rotated at runtime); on Tuwunel it preserves the existing runtime rotation flow via `MatrixOps.RegisterAppService`.
- **Synapse room deletion (DissolveRoom) always failed with 400**: `DELETE /_synapse/admin/v2/rooms/{id}` was sent with an empty body, but Synapse 1.127 parses that endpoint's body with `parse_json_object_from_request` (no `allow_empty_body`), returning HTTP 400 `M_NOT_JSON` "Content not JSON." The client now sends an explicit `{}` JSON object body, so `DissolveRoom` works on Synapse; the equivalence test now asserts a JSON body is present.
- **Synapse exclusive AppService users namespace blocked admin creation**: The Helm-rendered AS registration claimed the users namespace with `exclusive: true` over the broad default `@.*:<server>`. Synapse 1.127 rejects *any* other creation of an exclusively-claimed user ID — including the shared-secret admin bootstrap (`register_new_matrix_user -a`) and the admin API `PUT /_synapse/admin/v2/users/{id}` — with HTTP 400 `M_EXCLUSIVE` (no admin bypass), which made the admin user and every admin-provisioned user uncreatable on the default config. The users namespace is now `exclusive: false` (AS register/login only need the regex to match), restoring admin bootstrap and admin-API provisioning.
- **Synapse user re-provisioning silently killed device sessions**: `SynapseClient.EnsureUser` now sends `logout_devices: false` on `PUT /_synapse/admin/v2/users/{id}`. Synapse 1.127 defaults `logout_devices` to `true`, so every idempotent re-provision of an existing user (reconcile retries, worker/manager re-apply) invalidated the running device sessions; the flag keeps sessions alive when the same password is re-applied.
