## 1. 差异清单（Bridge 现状 vs Gateway 现状）

| # | 项 | Bridge 写法（现状） | Gateway 要求（现状） | 影响 |
|---|-----|--------------------|--------------------|------|
| 1 | SSE 订阅路径 | `/agi/gateway/v1/session/{id}/events`（`cimicode_stateless_adapter.py:39`） | `/agi/gateway/v1/sse/session/{id}/events`（`SessionEventController.java:43`） | 🔴 404 |
| 2 | 鉴权 Header | 裸 `eid` header（`cimicode_stateless_adapter.py:92-98`） | 应用级三件套 `X-App-Key`/`X-App-Secret`/`X-Operator-Eid`（或 SSO `X-Access-Token`） | 🔴 401 |
| 3 | model | 信封严格三字段不传 model | 不传则用 Session 冻结的 model（当前模板配的 `glm-4.7` 不在 Runtime 目录） | 🔴 422 |
| 4 | submit 路径 | `/agi/gateway/v1/turn/submit` | 一致 | ✅ |
| 5 | 幂等键 | `X-Idempotency-Key: UUID v4` | 一致 | ✅ |
| 6 | 请求信封 | `{"data":{sessionId,agentPrompt,userMessage}}` | CNASS 框架自动解 `Request.data`，兼容 | ✅ |
| 7 | 事件方言 | `type` 字段 + 终态三互斥 + 终态关连接 | 与 Gateway 实测 SSE 流完全一致 | ✅ |

## 2. 联调前必改的三处（Bridge 侧）

### 改动 ①：SSE 路径加 `/sse/` 段

`src/cimicode_bridge/runtime/cimicode_stateless_adapter.py:39`：

```python
# 改前
def events_path(session_id: str) -> str:
    return f"/agi/gateway/v1/session/{session_id}/events"

# 改后
def events_path(session_id: str) -> str:
    return f"/agi/gateway/v1/sse/session/{session_id}/events"
```

### 改动 ②：鉴权 Header 换应用级三件套

`cimicode_stateless_adapter.py` 构造器 + `_headers`：

```python
# 构造器加两个参数
def __init__(self, base_url, *, timeout_seconds=600, auth=None, eid="",
             app_key="", app_secret=""):          # ← 新增
    super().__init__(base_url, timeout_seconds=timeout_seconds, auth=auth)
    self.eid = eid
    self.app_key = app_key                        # ← 新增
    self.app_secret = app_secret                  # ← 新增

# _headers 改为
def _headers(self) -> dict[str, str]:
    headers: dict[str, str] = {"X-Idempotency-Key": str(uuid.uuid4())}
    if self.app_key and self.app_secret:          # 应用级鉴权（Gateway 现行）
        headers["X-App-Key"] = self.app_key
        headers["X-App-Secret"] = self.app_secret
        if self.eid:
            headers["X-Operator-Eid"] = self.eid  # eid 经 Operator 头传，不再裸传
    return headers
```

配套：`config.py` 的 `RuntimeConfig` 加 `app_key: str = ""` / `app_secret: str = ""` 两字段；`registry.py` 的 `build_runtime_adapter` 透传；`app.py` 的 `KNOWN_RUNTIME_PARAMETER_KEYS` 加 `"app_key": "appKey"` / `"app_secret": "appSecret"` 映射 + `_apply_bridge_section` 里补两行 binding。

### 改动 ③：信封加 model 字段（绕开模板模型配置错误）

`cimicode_stateless_adapter.py` chat() 的 submit body：

```python
json_body={
    "data": {
        "sessionId": session_id,
        "agentPrompt": agent_md,
        "userMessage": user_message,
        "model": "deepseek-v4-flash",   # ← 测试环境 Runtime 目录里唯一的模型
    }
},
```

（治本方案是 AgentHub 把专家模板的 model 从 glm-4.7 改成 deepseek-v4-flash，改完这处可删）

## 5. 排障速查（按现象查）

| 现象 | 原因 | 解法 |
|------|------|------|
| submit 返回 401 `SSO认证失败` | 没带 App-Key（改动②没生效） | 检查 `_headers()` 是否输出三件套 |
| submit 返回 403 `SESSION_OWNERSHIP_DENIED` | `X-Operator-Eid` ≠ Session 创建者 | eid 换成 E0040827，或用该 eid 重新 createSession |
| submit 返回 400 `MISSING_IDEMPOTENCY_KEY` | 幂等键缺失（不应发生，bridge 本来就带） | 检查 `_headers()` |
| SSE 返回 404 | 路径没加 `/sse/`（改动①没生效） | 检查 `events_path()` |
| Turn 执行后 FAILED（Pod 日志 CIMICODE_ERROR 422） | model 不在 Runtime 目录 | 确认改动③或修 AgentHub 模板 |
| SSE 只有 `:hb` 心跳没有事件 | Turn 已终态且 Stream TTL 过期（600s），或订阅的 session 没有活跃 turn | 先 submit 再订阅；或看 Pod 日志确认 turn 状态 |
| 流断且未见终态帧 → bridge 补了 turn_interrupted | 1800s 空闲超时或服务端异常断连 | 查 Gateway Pod 日志 `SSE 订阅结束` 行 |
| `httpx` 版本报错（stream 协议不匹配） | httpx≥0.28 与 httpx-sse 0.4.3 不兼容（adapter 注释 §8.3 已知问题） | `pip install "httpx<0.28"` |
